# Project: WES — Work Planning & Release (Core Bounded Context)

Core domain of a Warehouse Execution System: turns a shift's **charge** (volume
due by each deadline) into a **plan** (rate × heads per process path),
**releases work continuously** (waveless), and does **flow balancing** from live
buffer telemetry. Module `github.com/claudioed/wes-work-planning`.

> **Study project.** Educational DDD exercise using real WMS/WES/WCS
> terminology. Not a production system, not affiliated with any real company.

Domain source of truth: `/Users/claudioed/docs/amazon-fulfillment-ddd.md` and
`/Users/claudioed/warehouse-systems-ddd.md`. Use the ubiquitous language from
`.claude/rules/domain-model.md`; do not invent synonyms.

## Hard rules

### Architecture (NON-NEGOTIABLE)

- Hexagonal / Ports & Adapters, strict dependency rule: **domain depends on
  nothing; application depends on domain; adapters depend on
  application/domain.** No framework or SQL types in the domain layer.
- Read `.claude/rules/architecture.md` before touching any adapter or adding a
  bounded-context boundary (layer map, analytics data product ADR-0011, `web/`
  micro-frontend boundary).
- Read `.claude/rules/domain-model.md` before writing any use case or domain
  logic (aggregates, invariants, the eleven domain events, the seven
  control-loop use cases plus the queries and inbound-event use cases).
- `cmd/wes-projector` is the ONLY writer of the analytics DB; `cmd/wes-reports`
  is read-only.

### Contracts

- Specs are spec-first and Spectral-linted: `apis/openapi.yaml` (REST) and
  `apis/asyncapi.yaml` (Kafka events) are the sources of truth.
- The Docusaurus REST reference pages (`docs/docs/api/rest/*.api.mdx`) are
  GENERATED from `apis/openapi.yaml` by the `prebuild` npm script; never
  hand-edit them. AsyncAPI narrative pages (`docs/docs/api/events.md`,
  `docs/docs/ecosystem/integration-events.md`) are hand-written and must be
  updated whenever a message/channel changes.
- Errors: domain returns typed errors; the HTTP adapter maps them to RFC 7807
  `application/problem+json` (ADR-0005) — never a bespoke error shape.
- REST surface, published/consumed Kafka topics, envelope, idempotency, read-only
  projections (`LaborPlanObserved`, `UsableInventoryObserved`),
  `KAFKA_CONSUMER_GROUP` and `PATH_CATALOGUE_SOURCE=file|kafka`:
  `.claude/rules/integration-events.md`.

### Events: CloudEvents 1.0 is MANDATORY (ADR-0027)

Every Kafka message produced or consumed (integration `warehouse.<ctx>.events`
AND analytics — here `warehouse.wes.analytics`) is a CloudEvents 1.0 event in
structured content mode. Hard fleet rule, not a preference:

- No flat envelope, no dual-write, no dual-read, no envelope toggle env var
  (`EVENT_ENVELOPE_MODE` is gone).
- Build/validate/(un)marshal ONLY via `internal/adapters/kafka/cloudevents/`
  (sdk-go v2); transport stays kafka-go.
- Breaking payload change => new `.v2` type + new dataschema version, never
  mutate.
- Consumers dispatch on the FULL `type`, ignore unknown types, dedupe on `id`,
  and DLQ/skip (never crash, never parse a legacy shape) anything that fails
  CloudEvents validation.
- Required attributes, header, `type`/`dataschema` formats:
  `.claude/rules/cloudevents-envelope.md`.

### Testing and process

- Kafka-touching integration tests MUST use testcontainers
  (`testcontainers-go/modules/kafka`), never a skip-gated `KAFKA_BROKERS` check
  against an external broker — CI's `integration` job has no Kafka service, so
  a skip-gated test silently proves nothing there.
- Table-driven tests; at least one httptest integration test per endpoint; any
  new/changed aggregate invariant has a failing-path test.
- Definition of done: `go build ./...`, `go test ./...`, `go vet ./...` green;
  README updated if the change touches run instructions, env vars, or the API
  surface.
- Every run needs the process-path catalogue (ADR-0012): the default
  `PATH_CATALOGUE_SOURCE=file` refuses to start without `PATH_CATALOGUE_FILE`.
- GitFlow: `develop` is the default working branch, `main` is release-only.
- Read the relevant ADR before reversing a documented decision (32 ADRs, index
  in `.claude/rules/adrs-and-decisions.md`; ADR-0027 supersedes 0021 and the
  envelope parts of 0004).
- Run instructions, code standards, full testing detail:
  `.claude/rules/local-run-and-testing.md`.

## Commands

Local quality gate — **run before every commit**:

```sh
make check-fast  # fmt-check, vet, arch-test — fastest loop
make check       # fmt-check, vet, build, lint, test -race — run every change
make check-all   # + coverage gate (90%), arch-test, bdd — run before pushing
```

`make vuln` when touching `go.mod`; `make mutation` for the blocking mutation
subset. Proactively run `make check` yourself rather than relying on lefthook.

Fleet-wide rules: `.claude/rules/fleet/*.md` (canonical in IQVO/warehouse-docs `agents/fleet/`; never hand-edit).
