why it exists

Trucks leave on schedule, so work should be released by their deadline

The core bounded context of a Warehouse Execution System. It turns a shift's charge (volume due by each CPT truck-departure deadline) into a plan (rate x heads per process path), releases work continuously in priority order instead of batching it into waves, and performs flow balancing off live backlog telemetry - Drum-Buffer-Rope with CPT as the drum…

Today

It turns a shift's volume due by each truck departure into a rate-and-heads plan, then releases work in deadline order under a cap.

The catch

Hazmat, fragile and travel hints are off by default, and drift from the labor plan is flagged but not yet acted on.

what it does

Six capabilities carry work from forecast to finished unit

Charge forecasting

Takes in how much volume is due by each truck departure, per path

Shift planning

Commits rate and heads per path, never more people than installed stations

Waveless work release

Hands out one unit at a time by earliest deadline, capped so the floor isn't flooded

Work unit lifecycle

Tracks each unit from queued to done, closing it when the floor task completes

Flow balancing

Watches backlog live and recommends throttling upstream or moving labor

Throughput analytics

Publishes release-throughput and backlog-health reports from its own events

warehouse-systems · executive briefing · November 2026wes-work-planning
Charge forecasting: receive volume-due-by-CPT buckets per process path (ChargeForecast aggregate) Shift planning: commit rate x heads per path with plannedHeads <= installedStations invariant, reconciled against workforce-management's reported labor plan (PathPlanDriftDetected) Waveless work release: admit one unit at a time in earliest-CPT order on demand, bounded by a per-pool WIP limit as backpressure (ADR 0002, the defining decision) Work unit lifecycle: enqueue (idempotency-keyed), release, complete - consuming fulfillment-execution's TaskCompleted to complete units automatically Flow balancing: sample backlog telemetry, detect threshold breaches, rebalance decisions (ThrottleUpstream / ReassignLabor / NoActionNeeded) as a domain service, not a scheduled batch (ADR 0003) Analytics data product: release-throughput and backlog-health reports from its own domain events via a dedicated projector + read-only reports API (ADR 0011)
