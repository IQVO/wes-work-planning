# Documentation site — WES Work Planning & Release

The [Docusaurus](https://docusaurus.io) source for
<https://iqvo.github.io/wes-work-planning/>.

This directory **is** the docs folder for the repository and also the
Docusaurus project root. The Markdown pages live one level down, in
`docs/docs/`, which is Docusaurus's own content-directory convention.

```
docs/
  docusaurus.config.ts      site config (title, baseUrl, plugins, navbar, footer)
  sidebars.ts               the eight top-level categories, in order
  docs/                     the content
    overview/               introduction, what it does, layering, running locally
    business-context/       domain vision, ubiquitous language, the "why" pages
    ddd/                    subdomain classification, aggregates, events, read models
    api/                    API reference — REST (generated), Events, Error model
      rest/                 GENERATED from ../apis/openapi.yaml — do not hand-edit
    ecosystem/              context map, integration events, sibling services
    mcp/                    MCP governance charter
    analytics/              analytics data-product report contract
    adr/                    architecture decision records (Nygard template)
  src/                      homepage and custom CSS
  static/                   favicon, logo
```

## Local development

```sh
npm ci
npm start        # dev server on http://localhost:3000/wes-work-planning/
npm run build    # production build; fails on broken internal links
npm run typecheck
```

## The generated API reference

`docs/docs/api/rest/` is produced by
[`docusaurus-plugin-openapi-docs`](https://github.com/PaloAltoNetworks/docusaurus-openapi-docs)
from the repository's real `apis/openapi.yaml` — the same file Spectral lints
in CI. It is regenerated by the `prebuild` script on every `npm run build`, so
the reference cannot drift from the spec.

Regenerate it by hand with:

```sh
npm run clean-api-docs -- wes
npm run gen-api-docs -- wes
```

**Do not hand-edit anything under `docs/docs/api/rest/`** — change
`apis/openapi.yaml` instead.

## Deployment

`.github/workflows/docs.yml` builds this site and deploys it to GitHub Pages on
every push to `main` that touches `docs/**`, and on manual dispatch. The
repository's Pages source is configured to **GitHub Actions** (`build_type:
workflow`).

## Adding a page

1. Create the Markdown file under the right category in `docs/docs/`.
2. Add its id to the matching category in `sidebars.ts` — the sidebar is
   explicit, not autogenerated, so the eight top-level categories stay in a fixed
   order.
3. Run `npm run build` before pushing. Broken internal links fail the build by
   design (`onBrokenLinks: 'throw'`); fix the link rather than lowering the
   setting.
