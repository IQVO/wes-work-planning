The READ-ONLY analytical surface of wes-work-planning's "Release Throughput & Backlog Health" data product (ADR-0011), served by the separate `cmd/wes-reports` binary over a read-only Postgres pool against the analytical database. It is NOT the OLTP `cmd/wes` API documented in apis/openapi.yaml: a different binary, port and database (ADR-0038).

The report is a projection over this service's own domain events, delivered as CloudEvents 1.0 on the `warehouse.wes.analytics` topic and applied by `cmd/wes-projector`, the single writer. It is EVENTUALLY CONSISTENT, to a freshness target of p95 event-to-report lag under 30 seconds: read GET /reports/throughput/freshness to see how far the read model trails the event stream.

Rows are keyed by process path (`pathId`) and UTC hour bucket. Every counter is a count of events in that bucket. No route requires authentication (ADR-0016). Errors use RFC 7807 problem details (`application/problem+json`, ADR-0005).
